### A-orig. The 1.7 Hz / 0.30 V / fullwind outlier (OUT/IN ≈ 0.97)

A single run, `fullpanel-fullwind-amp0300-freq1700-per40-depth580-mstop30-run1.csv`,
dated 2026-03-27, `quality_flag=ok`. IN=15.95 mm, OUT=15.48 mm.

Per `MEMORY.md` ("f > 1.6 Hz at 0.2 V or 0.3 V is dubious — frequent dropouts"),
this is in the unreliable zone. There is also no nowind counterpart at 1.7 Hz/0.3V,
so it produces a hanging endpoint on the `damping_freq_all_30V` plot and a
single high-OUT/IN triangle on `damping_ka_full`.

**Decision needed**: drop 1.7 Hz from CH05 plots entirely (matches the stated
scope), or annotate it as out-of-scope and keep visible.

The 1.6 Hz bad-ultrasound filter (HIGH-priority H3 in the handoff) would
likely catch the per40 1.7 Hz runs as well — once the user provides the date,
both can be excluded together.

7 of 101 wave runs have measured OUT/IN > 1.0:

| 1 | 1.30 | 0.10 | full | 4.50  | 5.81  | 1.29 |
| 1 | 1.30 | 0.10 | full | 4.58  | 5.69  | 1.24 |
| 1 | 0.70 | 0.10 | full | 5.22  | 5.73  | 1.10 |

| 1 | 0.80 | 0.20 | full | 11.65 | 12.33 | 1.06 |

All are fullwind, low amplitude (0.10–0.20 V), low–mid frequency. Pattern

**Decision needed**: keep these visible (illustrates the wind-contamination
phenomenon) or filter at a fixed amp/freq cutoff. Caveat — the
`damping_freq` plot collapses across amps so the outlier shows as a noisy
point with a wide errorbar, not as scattered points.

### C. `ch05_damping_scatter_full` — missing secondary frequency axis

`_make_damping_scatter_fig` (plotter.py:347) plots vs `kL` but does not
call `add_freq_axis(ax)`. The other kL-axis plots (`_make_damping_freq_fig`
line 261, `_make_damping_wind_delta_fig` line 649) do. **Fixing.**

### D. `ch05_swell_scatter` save bug

`plot_swell_scatter` (plotter.py:1023–1051) saves three PDFs in a loop, all
named via `build_filename(f"swell_{band_name.lower()}", band_meta)`.
But `build_filename` returns `meta["figure_name"]` directly when set, and
`figure_name="ch05_swell_scatter"` is in `band_meta` for every iteration —
so all three writes go to `ch05_swell_scatter.pdf`. Only the last band
("Total") survives. The TeX stub then lists `ch05_swell_scatter.pdf` three
times. **Fixing** by appending the band suffix.

Spec says `save_plot → one PDF/PGF per band + one .tex stub with three
subfigures`. After the fix the three files will be:
`ch05_swell_scatter_swell.pdf`, `ch05_swell_scatter_wind.pdf`,
`ch05_swell_scatter_total.pdf`.

### E. `ch05_reconstructed` — wave and wind both red

`color_swell = WIND_COLOR_MAP.get(windcond, "black")` returns red for
`windcond="full"`. `color_wind = "darkred"` (when dual_yaxis is True).
Both lines in the figure are red-on-red — the only differentiator is
dash-vs-dot, which is visually weak.

**Fixing**: change `color_wind` default to a contrasting color (charcoal /
slate) regardless of dual_yaxis. The wind series is already on the
secondary y-axis — color difference is what makes the two readable.

Also: the y-axis label "Swell Amplitude" is technically wrong — the red
dashed line is the **paddle wave** reconstruction, which sits in the
"Wave" band (1.3 Hz here), not the lower-frequency swell band. The label
"Wave Amplitude" or "Reconstructed wave [mm]" would be clearer.

The figure currently uses run `fullpanel-fullwind-amp0200-freq1300-per240-depth580-mstop30-run1` —
a representative 1.3 Hz / 0.2 V / fullwind run. Top panel (IN, 9373/170)
shows ~15 mm wave with ~10 mm of wind chatter on the right axis. Bottom
panel (OUT, 12400/250) shows ~12 mm wave with only ~2 mm wind — the panel
sheltering effect from the handoff is visible.
