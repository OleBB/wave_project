### 4b. Simple table — long iteration

This took several turns. Sequence of changes:

1. **Added σ_Δ column** alongside Δ̄. Without σ_Δ, the table claimed
   "worst |Δ| = 2.07%" while the Bland-Altman figure showed dots at
   ±25%. Mismatch traced to: Δ̄ is the *mean* across runs (~0–2%);
   σ_Δ is the *per-run scatter* (~7–13%). Both numbers are needed.

2. **Renamed Δ → Δ̄** (math overline) so the column header explicitly
   advertises that it's a mean.

3. **Dropped ⟨A⟩ column.** Per user observation: "we don't run the
   same exact number of amplitudes for each frequency", so ⟨A⟩
   averages over an unbalanced amp-tier mix and doesn't represent a
   clean physical scale.

4. **Updated the IMMUTABLE block headline.** Was: `worst |Δ| : 2.07%`.
   Now: `worst row mean : |Δ̄| = 2.07%` AND `per-run scatter : σ_Δ =
   7.2–7.6%`. Two numbers, both signed for what they are.

5. **Two-section table (Uten vind / Full vind).** Was previously
   pooled across both wind conditions per row. The user spotted that
   the reader cares about agreement *with and without wind*. Split
   into row-groups using the same `\itshape` sub-section convention
   as the merged tables.

6. **Paddle-frequency filter.** Discovered that the original loader
   call `_load_psd_data_from_project(wind_label="nowind")` returned
   ALL nowind paddle runs, regardless of paddle frequency. So each
   row's σ_Δ was computed across runs paddled at any frequency,
   integrating the PSD at the row's target frequency band — which
   for paddle-at-other-freq runs is just noise floor. Filter added
   to load `target_freqs=[fh]` per row, restricting each row's run
   set to runs paddled at that specific frequency.
   - N values dropped from 32/48 (constant) to 6–17 (varies per row).
   - σ_Δ dropped (less noise contamination) — now 1–13% range.
   - Δ̄ values became more interesting (sign-flips between freqs
     under no-wind suggest standing-wave structure).

7. **Skewness analysis.** User asked the right question: "is σ_Δ
   bidirectional?" Discussion of Gaussian-vs-empirical reading. Added
   pooled skewness (`γ_1`) and empirical [P_5, P_95] percentiles per
   wind condition. Pooled across (amp × freq) per wind because
   amplitude is the dimension probes disagree most on, so summarising
   across it is desired. N = 32 (no-wind) and 48 (full-wind) — large
   enough for usable γ_1.
   - Pooled γ_1: nowind = −0.24 (≈ symmetric); fullwind = −0.91
     (moderately left-skewed → far probe systematically clips peaks).

8. **Variant A + Variant B.** Final structure today:
   - **Variant A** = simple table with `ka spenn` column added (Direction
     "annotate the existing table"). Same row layout, one extra column.
   - **Variant B** = NEW companion table (`ch04_parallel_probe_psd_agreement_by_ka_regime`),
     pooled by (regime × wind), where regime is decided per-run by
     `ka < 0.15` (wind-dominated) vs `ka ≥ 0.15` (wave-dominated). 4
     rows total with full distribution-shape stats (Δ̄, σ_Δ, γ_1, [P_5,
     P_95]). Tells the regime contrast directly.

   Both ship side-by-side. Captions deliberately short, suggested
   wording lives only in the IMMUTABLE TEX STUB. User decides which
   variant(s) to use in the thesis.

### 4c. The far-probe-clips-peaks finding

Physical interpretation hashed out via:
- Negative Δ̄ at high-ka × full-wind (means far probe reads lower than wall).
- Strong negative skewness (γ_1 ≈ −0.9 to −1.2 in the high-ka full-wind cells).
- User's domain knowledge: "one probe started struggling to read the
  steep rise after the trough".

Identifies probe `9373/340` (far) as the one that intermittently
clips peaks under steep-wave-with-wind conditions. Implication for the
thesis K_t: the canonical mean(A_far, A_wall) is a CONSERVATIVE (low)
estimate of A_in at f ≥ 1.5 Hz under full wind. Reported K_t in this
regime is therefore an upper bound on the true transmission — a
methodology caveat worth stating in chapter prose.

## Section 6 — durable rules established

Two rules that should propagate forward — already noted in MEMORY.md
and respected for the remainder of this session:

### Rule 1: Captions are user-owned

Triggered after the agent kept expanding `TABLE_CAPTIONS` text with
verbose descriptions. User pushback: "please dont add more caption
text in the caption, only as a suggestion in the TEX STUB."

Going forward:
- Caption suggestions go into the `meta.json` `sections` array under
  a `"Caption suggestion (for reference)"` block.
- The IMMUTABLE comment block at the top of each `.tex` file shows
  these as `% — Caption suggestion ` sections.
- `TABLE_CAPTIONS` / `FIGURE_CAPTIONS` dict values stay short and
  user-owned. Agents flag suggestions; users choose final wording.

### Rule 2: Distribution assumptions need empirical backing

Triggered after the agent floated "95 % limits of agreement = ±2σ"
in the Bland-Altman discussion. User pushback: "is our data gaussian?
how can we say 95% = ±2σ?"

Going forward:
- The 68/95/99.7 rule applies only to Gaussian distributions.
- For non-Gaussian or untested data, use empirical percentiles (P_5,
  P_95) instead of σ-based intervals.
- For asymmetry: skewness is the right concept, but at small N the
  estimate is noisy. Pool across appropriate dimensions before
  computing.

This rule is now baked into the simple table's IMMUTABLE block
("Reading [P5, P95]: empirical 90 % interval — no Gaussian
assumption.") and into the regime-table's analysis design.

## Notable corrections / lessons

1. **"worst |Δ|" was misleading.** The agent originally computed
   `max(abs(table['delta_pct']))` and called it "worst" — meaning
   *worst row mean*, but the wording invited misreading as "worst
   per-run". Lesson: when stub-writing a headline number, qualify it
   in the same line (e.g., "worst row mean", "per-run σ").

2. **`datasets:` field in stub was at the wrong granularity.** The
   field listed every folder loaded into `meta_results`, not those
   surviving the cell's filters. A 3-line patch (post-filter
   `pu.ACTIVE_DATASETS = ...`) fixed it. Lesson: stub provenance
   should reflect what's PLOTTED, not what's loaded.

3. **N=80 per row hid a paddle-freq mismatch.** Each row was integrating
   the PSD at its target band across ALL nowind/fullwind paddle runs,
   most of which had paddle elsewhere. Numbers looked plausible but
   weren't measuring "probe agreement on the paddle wave" — they were
   measuring "probe agreement at a band, across mixed paddle freqs".
   The paddle-freq filter (`target_freqs=[fh]` per row) was the right
   fix. Lesson: when a quantity feels too clean, check the run set.

4. **±2σ ≠ 95% without justification.** The agent floated the Bland-
   Altman convention without flagging the Gaussian assumption. User
   pushback established Rule 2 above. The fix: empirical percentiles.

5. **Caption expansion in TABLE_CAPTIONS** was an over-reach. Rule 1
   established: captions are user-owned. Suggestions go in the TEX
   STUB only.

## Workflow design observation (added late 2026-05-09)

User flagged a concrete pain point: editing a caption in
`FIGURE_CAPTIONS` / `TABLE_CAPTIONS` and getting it into the rendered
`.tex` stub currently requires re-running the underlying data /
figure script. For tables already in the render-only pipeline
(`main_save_tables.py` cells), this is fast (~50 ms). For figures and
for tables still bound to `main_save_figures.py` cells, it triggers
data reload — wasteful for what is just a caption tweak.

User wants a "more user-based" system: edit caption, see it land
without re-rendering data/figure. The render-only table pipeline is
the proof-of-concept; needs extending to figures.

Concrete instance flagged: `ch04_amp_methods_a1_fullwind` caption
edited in `FIGURE_CAPTIONS`; .tex stub on disk still has the old
version because the figure script hasn't been re-run.

Captured in `memory/workflow_caption_only_edits_design_note.md` with
4 path-forward options sketched. Recommended: an in-place caption
patcher with sentinel-bracketed `\caption{...}` blocks.

**Until that lands, the caption update for `ch04_amp_methods_a1_fullwind`
specifically requires re-running its figure script.**
